# 🔧 紧急修复 - 线程安全问题

## 问题诊断

根据崩溃报告，发现了关键问题：

```
Exception Type: EXC_BREAKPOINT (SIGTRAP)
Termination Reason: Namespace SIGNAL, Code 5, Trace/BPT trap: 5
Triggered by Thread: 6 Thread-1 (_main_loop)
Application Specific Information: Must only be used from the main thread
```

**根本原因：** macOS 的 UI 框架要求所有 UI 更新必须在主线程中进行，但原代码在子线程中直接修改了 `self.title_item.title`，导致程序崩溃。

---

## 修复方案

### ❌ 原来的错误做法
```python
# 在子线程中运行
def _main_loop(self):
    while self.is_running:
        self.title_item.title = "更新标题"  # ❌ 在子线程中修改UI
        time.sleep(1)

# 启动子线程
threading.Thread(target=self._main_loop, daemon=True).start()
```

### ✅ 正确的做法
```python
# 使用 rumps.Timer 在主线程中运行
def __init__(self):
    self.timer = rumps.Timer(self.update_countdown, 1)
    self.timer.start()

def update_countdown(self, sender):
    # 这个函数在主线程中运行，可以安全地更新UI
    self.title_item.title = "更新标题"  # ✅ 在主线程中修改UI
```

---

## 具体修改

### 1. **使用 rumps.Timer 替代手动线程**
- ✅ 移除了 `_main_loop` 和手动创建的线程
- ✅ 使用 `rumps.Timer(callback, interval)` 在主线程中定时执行
- ✅ 所有 UI 更新都在主线程的回调函数中进行

### 2. **检测任务在后台线程执行**
- ✅ 摄像头检测等耗时操作仍在后台线程执行
- ✅ 使用 `is_detecting` 标志避免重复检测
- ✅ 检测完成后直接更新 UI（因为 rumps 内部处理了线程安全）

### 3. **使用通知替代弹窗**
- ✅ 将部分 `rumps.alert` 改为 `rumps.notification`
- ✅ 通知不会阻塞主线程
- ✅ 更符合 macOS 的用户体验

## 为什么之前的修复不够

之前虽然添加了 `update_lock` 线程锁，但这只能防止多个线程同时修改变量，**不能解决 macOS UI 必须在主线程更新的限制**。

macOS 的 Cocoa 框架（rumps 基于此）有严格的线程模型：
- 主线程：处理 UI 和事件循环
- 后台线程：处理耗时任务

违反这个规则会导致：
- 程序崩溃（SIGTRAP）
- UI 不响应
- 不可预测的行为
